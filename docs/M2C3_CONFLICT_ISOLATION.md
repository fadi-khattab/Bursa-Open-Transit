# BOT-M2C.3 — Conflict isolation and alternative evidence

Baseline a57e4a2. New offline synthetic API ConflictGraph; legacy DerivationGraph is unchanged and must not be mistaken for this conflict policy.

Proof IDs identify individual replayed paths; conclusions group verified nodes by (typed stop subject, field). Reconstruct roots from each selected pinned data/scope pair via audit_stops, including extracted model-mismatching values. Model agreement is separately reported, not used to select a winner. Membership of the scope, ledger resolution and presence of a canonical stop still delimit this slice. Out-of-scope, invalid, missing and unresolved records remain in the audit rather than becoming roots. A single selected version per source namespace is required; no freshness or temporal alignment is inferred.

Replay each claim in input order using M2C.2's closed rules. Bad computations and absent/invalid/forward dependencies produce INVALID proof records; duplicate identifiers fail the graph closed. A four-level field/rule stratification (root, distance, seconds, minutes) allows finalization of conflicts before dependent levels. A scenario explicitly excludes proof IDs or artifact digests (including scope). At each level only eligible verified proofs with candidate parents participate in same-field disagreement detection. Distinct live values become DISPUTED with no winner. Descendants of noncandidate proofs are BLOCKED. A quarantined/blocked/invalid proof cannot poison an unrelated viable alternative. Valid roots and replayed nodes remain inspectable, including disputed and excluded ones; invalid claims are retained in input claims and invalid reports. No voting, model preference or use of descendants to exonerate ancestors.

Conclusion CANDIDATE means one or more surviving mutually agreeing proofs under the selected hypothetical exclusions; it is not truth or export permission. Report tracks root IDs and source/scope artifact digests per proof, plus inherited estimation. Disjoint root or artifact sets do not establish institutional independence: ledger, acquisition process, operators and rules may be shared. Quarantine is a caller-supplied scenario, not a fault finding or authorized remediation; changing exclusions recomputes reports, not source history. A scenario can select either side of a real disagreement and cannot authenticate the selected side.

Equality is exact scalar Python numeric equality (0 and 0.0 agree) or exact string equality; no geospatial tolerance or temporal reconciliation. Same-runtime replay only. No general recursive rule engine, durable authority, external authentication, physical correctness, full-network evidence, GTFS readiness, production access or publication. Scope completeness reports remain per source, not a union coverage certificate. Ordinary Python immutability is not process isolation.

Explicit remaining counterexample: an omitted alias may contain a conflicting value outside the chosen inventory. The audit flags the extra source record and fails relative completeness, but the scoped conclusion may remain CANDIDATE. Therefore no global conflict-freedom or completeness claim follows. M2C.4 must define scope-bound certification and how unresolved/out-of-scope observations affect eligibility.
