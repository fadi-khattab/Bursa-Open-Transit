# BOT-M2C.5A — Checkpoint-bound persistent coverage replay

SQLite append-only journal of complete normalized synthetic coverage audit inputs and outputs. A single atomic row contains pinned source/scope/reference bytes, canonical model, ordered identity events, observations, conflicts and relative certificate. On read, reconstruct typed network and ledger and replay M2C.4; never trust stored reports alone. Hash chain commits sequence, previous digest and canonical payload. Compare-and-append uses BEGIN IMMEDIATE and requires an exact caller-retained checkpoint; read-only verification uses a consistent transaction. Explicit exclusive initialization; missing storage is not silently recreated. Reject identity history truncation or replacement and changed bytes under an already recorded namespace/version. Failed relative audits are retained too.

Threat boundary: triggers are accidental-mutation guards, not security against file owners. A separately retained trusted checkpoint detects rollback and full replacement, but a checkpoint supplied by the same attacker cannot. No external witness service, signing, crash-safe cross-resource checkpoint protocol, or authentication of institutional data is implemented. Commit may succeed before the caller retains its new checkpoint; verification then fails closed, with recovery not yet implemented. A new database starts at the common genesis; checkpoints do not establish database identity before its first entry. No permission to publish, no live data, no self-hosted runner.

Scope: persists M2C.4 coverage only; M2C.2/3 proof and scenario replay is still pending, as are independent verifier implementation, durable witness and GTFS readiness. Exact replay assumes compatible Python serialization and model policy. Whole-history replay and duplicated artifacts deliberately favor simplicity over scale; no migration, retention, or production performance guarantees.
